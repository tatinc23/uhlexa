**Goal:** A working Uhlexa demo: FastAPI + Postgres + real MCP server + web simulator + Family Board, where Alex's
agent resumes Jordan's agent's "Sunday groceries" thread, gets approval, and runs a Maritime browser task (or an honest
takeover/unavailable state).

**Architecture:** One FastAPI app (REST + MCP Streamable HTTP + static simulator) over SQLAlchemy/Postgres; services
call a policy engine (final authority) and three feature-flagged provider adapters (SubQ Snap, Primitive, Maritime);
long work runs through a `jobs` table drained by a worker (compose service, or embedded on Manufact).

**Tech Stack:** Python 3.12, uv, FastAPI ≥0.159, SQLAlchemy ≥2.1.6, Alembic ≥1.20, Pydantic ≥2.14,
pydantic-settings ≥2.16, psycopg[binary] ≥3.3, httpx ≥0.28, mcp ≥2.3,<3; pytest ≥9.1, ruff; Docker, compose,
postgres:17-alpine.

**Spec:** `docs/superpowers/specs/2026-10-22-uhlexa-design.md` (read it first). Provider wire facts:
`docs/research/2026-10-22-{primitive,maritime,subq,keiki-neon-manufact}-facts.md` — they override any assumption here.

## Global Constraints

- Repo layout exactly as spec §3 (package `app/` at repo root; simulator in `web/simulator/`; Family Board HTML in
  `app/templates/family-board.html`). Run commands from the repo root.
- Python 3.12 (`.python-version` = `3.12`; Docker `python:3.12-slim`). `uv run …` for every command.
- MCP SDK 2.x API only: `MCPServer`, `Context`, `mcp.server.apps.Apps` (no FastMCP). Verify against the installed
  package source, never memory.
- `.env.example` contains the brief's environment contract verbatim (spec §5) plus an "Uhlexa extras" block.
- PostgreSQL is authoritative; schema portable to SQLite (`sa.Uuid`, `sa.JSON`, `DateTime(timezone=True)`, string
  enums `native_enum=False`).
- Services `flush()`; the request handler / MCP tool / job commits once. No business logic in routers or tools.
- Every query is household-scoped through the Principal; foreign ids ⇒ `NotFound` (404).
- No secrets in git, logs, API responses, or the browser. Provider keys only via settings.
- No fake success: disabled ⇒ `disabled`, flag on + no key ⇒ `misconfigured`, live failure ⇒ `unavailable`.
- No LangChain, Redis, Kafka, event bus, microservices, Keiki/Inkbox/Ring/FireTV adapters.
- Commit after each task; message ends with `Co-Authored-By: Claude <noreply@anthropic.com>` (orchestrator commits
  in overnight mode; builders do not commit).

## Review Focus

1. **Double approve / double start** (two clicks, two tabs, MCP + UI at once): second call ⇒ 409, exactly one
   `browser_task_run` job, one approval event. → Task 5 `test_double_approve_enqueues_once`.
2. **Request with no parseable items** ("add stuff to groceries", "add  and  to groceries"): task created as
   `shopping_list` with `metadata.items == []`, agent reply asks which items, **no** browser task can start (409
   "no items to add"). → Task 5 `test_no_items_blocks_browser_task`.
3. **Hostile or huge text** (`<img onerror>`, 5 000 chars, emoji): stored escaped-safe, API returns it verbatim,
   UI renders as text, over-limit ⇒ 422. → Task 6 `test_message_text_limits_and_html_roundtrip`; Task 8 uses
   `textContent` only.
4. **Provider flag on but bad/missing key or provider 5xx**: status `misconfigured`/`unavailable` with reason, flow
   continues on fallback, no 500. → Task 9/10/11 contract tests `*_provider_error_is_unavailable`.
5. **Worker dies mid-job** (job `running` with stale `locked_at`): reclaimed after `JOB_LEASE_SECONDS=120`, attempts
   +1, after `max_attempts` ⇒ job `failed` and browser task `failed` with reason (never stuck "running").
   → Task 5 `test_stale_job_is_reclaimed_then_failed`.
